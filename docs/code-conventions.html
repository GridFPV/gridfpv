GridFPV

Code & Repo Conventions

Internal · how the Rust workspace is organized and the conventions every crate follows

The implementation conventions that hold across the codebase — the companion to Doc Authoring Conventions. Recorded as they were established through v0.1–v0.2 so new crates and contributors stay consistent.

1. Workspace & crates

A Cargo workspace of gridfpv-* crates. The spine lives under crates/: events (the canonical event model), storage (the append-only log + SQLite), projection, engine (the race engine — heat loop, scoring, marshaling, format generators, scheduling), adapters (timer adapters), and app (which builds the single gridfpv binary). xtask/ and testkit/ (the shared mock-RH test harness) are non-published (publish = false) helper crates. Internal dependencies are path deps declared once in [workspace.dependencies] and inherited with name.workspace = true.

Edition & metadata set once. Rust edition 2024, MSRV 1.85, resolver = "3". Edition, MSRV, license (AGPL-3.0-or-later) and repository are set in [workspace.package] and inherited per-crate via field.workspace = true.

2. Checks — one source of truth

cargo xtask defines every check. Local and CI run the identical suite: cargo xtask ci = fmt --check && clippy --all-targets -D warnings && test --all && the Rust→TS bindings drift-check. The GitLab pipeline is thin — it only calls cargo xtask ci. Never put check logic in .gitlab-ci.yml; add it to xtask so local and CI can't drift.

3. Generated wire types

Rust→TypeScript via ts-rs, drift-gated. Wire types are generated from Rust with ts-rs, derived only on the canonical event model in gridfpv-events, exported to repo-root bindings/. cargo xtask gen regenerates; cargo xtask ci fails if the checked-in bindings/*.ts drift from the Rust types. Commit regenerated bindings with the Rust change.

4. Safety & the data model

No unsafe. Every crate begins with #![forbid(unsafe_code)]; the spine carries no unsafe.

Integer-microsecond source time. Time is carried as SourceTime — integer microseconds on the source's own clock (i64). Interval math uses no floats, so comparisons are stable and tests are byte-deterministic. It is serde-transparent / ts(as = "i64"), a bare number on the wire.

Externally-tagged events; observations only. The canonical Event enum is externally tagged ({"Variant": {…}}), mapping to a TypeScript discriminated union. Adapters emit raw observations only (no laps or results); optional detail (sequence, gate, signal) is skip_serializing_if-omitted at its default to keep the common case compact.

Event naming: states for our state machines, past-tense facts elsewhere. A transition of a state machine we run is named for the state it enters — the heat loop's HeatTransition uses Running/Finished, not Started/Landed (its off-ramps stay action-named: Aborted/Restarted/Discarded). Everything else — observed source lifecycle (SessionStarted/SessionEnded), marshaling adjudications (DetectionVoided, PenaltyApplied) — stays past-tense (the event-sourcing default for facts). The engine's command API is imperative (stage/arm/start/finish) and produces these state events.

5. Live & container tests

Network/Docker tests sit behind a live feature. The real network transports (Socket.IO for RotorHazard, WebSocket for Velocidrone) and the container-backed tests are gated by an optional live Cargo feature, off by default — so the core suite stays dependency-light and hermetic and runs everywhere. The shared pipeline runs default-feature checks only; cargo xtask live runs the live tests (mock-WS + dockerized-RotorHazard) locally. See Testing Strategy §5.
