Protocol

Internal design doc · the one read/realtime contract · draft

The single read/realtime contract that every client speaks — served identically by the Director on the LAN and by the Cloud off-LAN. "One protocol, two transports" made concrete: message shapes, the realtime channel, auth, and versioning.

Early draft. This page captures scope and the open decisions routed here from the Architecture doc (see §6 and §9), so they're tracked in the right place. The contract itself is not yet specified. When this doc and the Vision disagree, the Vision wins.

Scope

This doc will own:

  • The snapshot read model — how a client fetches the current state of the projections it cares about.
  • The realtime change stream — how live updates are pushed after the snapshot.
  • Subscription scoping — which projections / events a given client subscribes to (a spectator vs an overlay vs the RD console).
  • Auth & authorization — the RD's privileged control path vs open/lightly-tokened reads, and how scoping differs on LAN vs Cloud.
  • Versioning & evolution — keeping the contract stable as both transports and every client evolve.

The wire types are defined once in the Rust server crate and generated into TypeScript, so the Director, the Cloud, and all clients share one definition (see Architecture §6).

Open decisions

  1. Realtime transport — WebSocket vs SSE. Working default (set in Architecture): WebSocket, snapshot + change stream. Decide whether a read-only one-way fit (SSE) is simpler for spectators/overlays, or whether one transport should serve all clients.
  2. Snapshot + change-stream envelope shape. Full-state vs delta updates, how a client resumes mid-stream, ordering/sequence guarantees, and how the change stream relates to the underlying append-only log offsets.
  3. Auth mechanism. How the RD role authenticates, token / session format, and how read access is scoped on the LAN (open? lightly tokened?) vs the Cloud (accounts). Trust boundaries are fixed in Architecture §9; the mechanics are decided here.
  4. Subscription scoping & filtering. How a client narrows to one class / heat / pilot, and pagination for large reads (full event history, open-data queries).
  5. Contract versioning. How the snapshot/stream are versioned so an older PWA and a newer Director (or vice versa), and the Cloud relay, stay compatible.
