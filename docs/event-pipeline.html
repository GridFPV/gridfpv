Event Pipeline

Internal design doc · what an event is and what each phase must do

What it actually means to run an FPV race event in GridFPV — the phases an event moves through, and the specific capabilities we want to hit at each one. The same definition covers real-world (IRL) racing and Velocidrone virtual racing.

This doc defines the pipeline at the level of intent and capability — the ideas we must hit. It deliberately leaves the data model, the timer-adapter spec, protocol message shapes, and the Cloud warehouse to their own docs (see Architecture, Timer Adapters — coming soon). When this doc and the vision disagree, the Vision wins.

Overview — the model

An event is not a straight line. It is a mostly-linear progression of phases (some optional, some you can import instead of running), with a recurring heat loop reused inside several phases, and a few concerns that run throughout. The flow is circular at points: inside the mains you run a heat, score it, advance, and run the next.

The phases:

  1. Setup & Registration required — stand up the event and its field.
  2. Practice optional — non-binding flying before anything counts.
  3. Qualifying optional — establish a ranking: run it live, import it (e.g. a Velocidrone leaderboard), or skip it.
  4. Brackets / Mains the racing — seed from qualifying, generate the bracket, run it, advance to a winner.
  5. Championship / Season optional — aggregate results across many events.

The recurring heat loop — schedule → stage → arm → race → land → score → advance → next — is the engine that runs inside Practice, Qualifying, and Mains. It is reusable machinery, not a single phase; that is why running heats shows up again and again below rather than as one step.

Concerns that run throughout — Results & Standings, Streaming/Broadcast, and External Sync (MultiGP) — are not phases either. They accumulate and update continuously across the whole event. They are folded into the phases below where relevant, and recapped at the end.

Phase 1 — Setup & Registration

required Stand up the event and assemble the field.

Everything starts here: defining the event and getting pilots into it. A guided setup wizard should make the common path effortless (it's table stakes against the incumbents), while leaving every choice editable.

Define the event

  • Name, classes / categories (e.g. Mini, Micro, Wing — or a sim class), and the date.
  • Format configuration — which phases are enabled (is there practice? qualifying or an import? what mains format?). The pipeline is configurable, not fixed.
  • Track selection — a physical track layout for IRL, or a Velocidrone spec track (with its track id) for sim.

Assemble the field

  • Add pilots from the global pilot registry, or let them self-register via the racer app.
  • Import a roster — from MultiGP RaceSync (chapter roster) or from a Velocidrone room / leaderboard.
  • Check-in & presence — mark who's actually here. Support auto-presence: pilots a timer or sim room currently sees can be activated automatically ("everyone in the room at 8 PM gets bracketed").
  • Pilot-identity binding — bind each timer's local pilot reference (a node seat, a sim player name) to a GridFPV pilot, per the adapter model.

IRLDeclare the available frequency / seat pool here, and capture waivers and the safety briefing.

SimPick the spec track; no frequency pool, no waivers — registration is mostly roster + presence.

Phase 2 — Practice

optional Non-binding flying before anything counts.

Practice exists so pilots warm up, shake out gear, and get familiar with their seat and frequency before results matter. It runs the heat loop, but nothing it produces counts toward seeding.

  • Open / rolling "fly when ready" sessions — pilots cycle through without a fixed schedule.
  • Optional informal best-lap display so pilots can gauge themselves, clearly marked as non-binding.
  • Results are discarded from scoring (though raw laps can still be logged).

IRLA natural moment for per-pilot timer calibration — the system learns each pilot's signal so real races read cleanly.

SimFree-fly / hot laps on the track; no calibration needed.

Phase 3 — Qualifying

optional · importable Establish a ranking that seeds the mains.

Qualifying produces an ordered ranking of the field — the seeding that the mains are built from. Crucially, there are three ways to get that ranking, and we treat them as equals:

  • Run it live — fly qualifying heats through the heat loop.
  • Import it — pull a ranking from outside. A Velocidrone leaderboard import is first-class here (fixed sim tracks make this natural); MultiGP results are another source.
  • Skip it — seed from registration order or a manual seed, and go straight to the mains.

Formats (when run live)

  • Timed — best single lap, or fastest N consecutive laps (commonly 2 or 3).
  • Rounds-based — a fixed number of rounds, best result kept.
  • Group / round-robin — pilots split into groups, ranked by combined finishing position.
  • Rolling / ZippyQ — "fly when ready" queue with a pack limit, queue depth, and rest-between-rounds; the RD can add rounds on demand as pilots keep flying.

Whatever the format, qualifying aggregates each pilot's flights into a single qualifying metric and position, which becomes the seed for Phase 4.

Sim"Leaderboard bashing" — pilots grind a spec track and the leaderboard is the qualifying ranking; importing it should be one click.

Phase 4 — Brackets / Mains

the racing Seed, build the bracket, run it, crown a winner.

This is the competition proper. It begins by turning the seeding into a structure, then runs that structure to a result.

Seed & generate the bracket

The mains start by seeding the field (from qualifying, an import, or a manual order) and generating a bracket — the rounds and heats pilots will fly. This generation step is what "seeding & brackets" means: it's the entry to the mains, not a separate phase.

  • Formats (a pluggable registry of generators): round robin, single elimination, double elimination, multi-tier mains (A/B/C/D/E with top-N advancing up a tier), Chase-the-Ace finals, and MultiGP/FAI P9–P16 style brackets.
  • Configuration — pilots per heat (4 / 6 / 8 / 10), how many seeds advance from each heat, and the finals format.
  • Manual adjustment — re-seed or move pilots between heats before they fly.

Run & advance (the loop)

Each heat runs the heat loop; results feed an advancement step that generates the next heats per the format's rules — run → result → advance → run, until a winner falls out. This is the circular heart of the pipeline.

  • Live race control — staging countdown, arm, race, land; abort / restart; discard and re-run a heat.

IRLAssign a frequency / channel per heat and avoid conflicts; marshaling with lap correction — add / remove laps, adjust enter/exit points, recover missed laps from signal history.

SimNo frequency management; heats can fire back-to-back; marshaling is lighter — mostly abort / restart.

Phase 5 — Championship / Season

optional · cross-event Aggregate across many events.

Beyond a single event, GridFPV should link events into a season and compute standings across all of them: points systems, season leaderboards, and qualification pathways (the equivalent of a Global Qualifier feeding a championship).

This phase leans on the optional Cloud — the analytics warehouse and season linking — so it is intentionally light here and will get its own treatment alongside the Cloud design (Architecture, coming soon). The single-event pipeline above stands on its own without it.

Concerns that run throughout

These aren't phases — they accumulate and update continuously across the whole event.

Results & Standings. Every heat's result is captured as it finishes; standings recompute continuously so live leaderboards, event standings, and overlays are always current. Results are exportable at any point.

Streaming / Broadcast. Overlays — staging, leaderboard, split-screen, podium, results, brackets — are driven by whatever is live right now, spanning qualifying through mains to the podium. Includes OBS control and a path to capture / RTMP inputs.

External Sync. MultiGP RaceSync — roster import at setup, and pushing results (pilots, heats, lap times, placements) during and after the event. Plus open data export and the optional one-way push of the append-only log to the Cloud.
